# Toolstack

This repository is a local analytics case-study workspace for building governed
business metrics with dbt, MetricFlow, Airflow, Postgres, and a small
conversational BI prototype.

## Repository Layout

| Path | Purpose |
|---|---|
| `single-dbt-opensource/` | Main runnable analytics stack: Docker Compose, Airflow DAGs, dbt project, MetricFlow semantic layer, CI notes |
| `single-dbt-opensource/dbt/` | dbt models, tests, seeds, snapshots, semantic models, metrics, and launch gates |
| `single-dbt-opensource/airflow/` | Airflow DAGs that orchestrate bronze loading and dbt builds |
| `common/` | Shared setup guides and bronze database scripts used across case studies |
| `conversational-bi/` | FastAPI + HTML/JS prototype that turns natural-language questions into governed MetricFlow queries |
| `logs/` | Local runtime logs; should be treated as generated output unless intentionally preserved |

## Runtime Stack

| Tool | Where | Role |
|---|---|---|
| Docker Compose | `single-dbt-opensource/docker-compose.yml` | Starts the local data platform services |
| Postgres with pgvector | `postgres` service using `pgvector/pgvector:pg17` | Local warehouse/database for bronze, silver, gold, seeds, snapshots, and Metabase metadata |
| Airflow | `airflow-webserver`, `airflow-scheduler`, `airflow-init` services | Orchestrates data loads and dbt runs |
| dbt Core | Airflow image venv at `/usr/local/airflow/dbt_venv` and local dbt project | Builds staging, intermediate, mart, seed, snapshot, test, and semantic artifacts |
| MetricFlow | dbt semantic layer and `mf query` | Governed metric query interface used by the BI prototype |
| Metabase | `metabase` service | Local BI/dashboard surface on port `3000`, direct to Postgres |
| Hex | Cloud-hosted | Cloud BI/notebook surface; reaches local Postgres via tunnel (ngrok/Tailscale) or a mirrored cloud warehouse |
| LangGraph | `conversational-bi/` backend | Agent orchestration for multi-step metric investigations (branching, state, tool loop) |
| pgAdmin | `pgadmin` service | Database inspection surface on port `5050` |
| GitHub Actions | `single-dbt-opensource/.github/workflows/` | Self-hosted CI for dbt PR validation and production Airflow trigger |

## Governed Metrics

The semantic layer currently covers three domains:

| Domain | Examples |
|---|---|
| Revenue | gross revenue, net revenue, revenue per customer, week-over-week and month-over-month changes |
| Token usage | tokens consumed, API requests, input/output tokens, error rate, tokens per request |
| Quota | effective request/token limits, peak utilization, pending requests, actual requests/tokens |

MetricFlow is the governed query surface. The conversational BI app should execute
only through MetricFlow, not by generating raw SQL.

## Conversational BI Prototype

The conversational BI prototype lives in `conversational-bi/`.

| Component | Path | Purpose |
|---|---|---|
| FastAPI app | `backend/main.py` | Serves `/`, `/health`, `/catalog`, and `/query` |
| Catalog builder | `backend/catalog_builder.py` | Converts `target/semantic_manifest.json` into compact YAML for the LLM |
| LLM client | `backend/llm_client.py` | Supports Ollama, OpenAI-compatible APIs, OpenCode Go auth, and an Anthropic path |
| Query translator | `backend/query_translator.py` | Validates metric names, resolves time ranges, creates `mf query` commands, parses results |
| Eval runner | `backend/eval_runner.py` | Runs NL-to-metric evaluation fixtures |
| Frontend | `frontend/index.html` | Single-page HTML/JS report and chat interface |

Python dependencies:

| Package | Purpose |
|---|---|
| `fastapi` | API server |
| `uvicorn` | ASGI server |
| `pydantic` | Request/response models |
| `PyYAML` | Catalog serialization |
| `httpx` | LLM provider HTTP calls |
| `langgraph` | Multi-step agent orchestration (branching investigations) |

LLM provider is **BYOK / pluggable** (OpenAI-compatible, Anthropic, or local).
No provider is hardcoded; selection is by config/env. The LLM maps natural
language to a governed metric plus dimensions and time range only — it never
generates warehouse SQL.

BI surface connectivity:

| Surface | Where | Connects via |
|---|---|---|
| Metabase | Local (Docker Compose) | Direct to Postgres `postgres:5432`, db `btg_resource_utilization` |
| Hex | Cloud | Tunnel (ngrok/Tailscale) exposing the Postgres port, or gold mirrored to a cloud warehouse. Register host/port/user/db as a data connection in Hex; scope a read-only role to `mart_gold` |

Known follow-ups:

- Fix the Anthropic method call/signature mismatch before using Anthropic as a provider.
- Replace or parameterize the fixed reference date used for relative time ranges.
- Expand the eval suite before using the prototype for real business decisions.
- Add a `conversational-bi/RUNBOOK.md` for restart, catalog rebuild, provider setup, and failure diagnosis.

## CI/CD

The CI/CD plan is documented in `single-dbt-opensource/5_cicd.md`.

| Workflow | Trigger | Purpose |
|---|---|---|
| `dbt_ci.yml` | Pull requests to `dev` or `main` touching dbt paths | Runs dbt deps and modified-model or full dbt build on a self-hosted runner |
| `dbt_prod.yml` | Push to `main` or manual dispatch | Triggers the Airflow `pipeline_daily` DAG and saves a production manifest |

The intended branch flow is:

```text
personal schema -> feature branch -> pull request -> CI -> dev -> release PR -> main -> Airflow production DAG
```

## Local Verification Commands

Run from `single-dbt-opensource/` unless noted otherwise.

```bash
docker compose ps
```

```bash
cd dbt
dbt deps
dbt debug
dbt parse
dbt build
mf validate-configs
```

Smoke-test governed metrics:

```bash
mf query --metrics total_net_revenue --group-by metric_time
mf query --metrics total_tokens_consumed --group-by metric_time
mf query --metrics effective_requests_per_minute --group-by metric_time
```

Run the conversational BI API from the repository root:

```bash
cd conversational-bi
uvicorn backend.main:app --reload --port 8000
```

Then visit:

```text
http://127.0.0.1:8000/
http://127.0.0.1:8000/health
http://127.0.0.1:8000/catalog
```

## Launch Gates

The current launch gate source of truth is:

```text
single-dbt-opensource/dbt/LAUNCH_GATES.md
```

Before production use, keep these gates green:

| Gate | Bar |
|---|---|
| Semantic layer | `dbt parse`, `mf validate-configs`, and smoke metric queries pass |
| LLM selection | Hosted model meets the measured accuracy and hallucination thresholds |
| Rejection behavior | Unanswerable questions are rejected at the required rate |
| Operational readiness | API runbook, catalog rebuild path, latency check, and BYOK docs exist |
| Governance | Unknown metrics are blocked before `mf query` execution |
