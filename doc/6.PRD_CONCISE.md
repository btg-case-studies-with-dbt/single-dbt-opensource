## Problem Statement

RevOps/finance, engineering/capacity, and customer-facing teams at an AI-inference platform each read the same underlying business reality — revenue, token usage, quota/capacity — through separate dashboards and tools whose metric definitions were never governed in one place, so a simple cross-domain question takes minutes to hours of dashboard-hopping, ad-hoc SQL, and analyst reconciliation, and different tools can disagree about the same number. V1 solves the narrowest slice of this: a natural-language question answered by exactly one governed MetricFlow metric, proving that an LLM can route reliably before any richer investigation capability is built.

## Goals

- Answer a natural-language business question with exactly one governed metric value, executed only through MetricFlow.
- Cover the three domains whose semantic models and metrics already exist: revenue, token usage, quota/capacity.
- Reject, rather than approximate, any question that does not map cleanly to a known governed metric.
- Resolve relative time ranges ("last week," "this quarter") against a real reference date.
- Keep the LLM provider pluggable (BYOK: OpenAI-compatible, Anthropic, or local) with no provider hardcoded.
- Prove the core assumption — cross-domain routing accuracy — on a domain-balanced eval set before any launch decision.

## Non-Goals

- Multi-step "why did X happen?" investigations or any agent/tool-loop behavior (LangGraph). Deferred to a later release.
- Root-cause narratives or synthesized explanations across multiple metrics.
- Customer-service questions or metrics — no semantic model or governed metrics exist yet for this domain.
- Any raw SQL generation against the warehouse, by the LLM or otherwise.
- Automatic creation or modification of metric definitions.
- Disambiguation dialogue for ambiguous questions — v1 rejects ambiguous questions in a single pass rather than asking a clarifying follow-up (see PR/FAQ Internal FAQ for rationale).
- Production SaaS deployment, multi-tenant hosting, pricing, packaging, or any external launch claim.

## Target User / Persona

- **RevOps/finance analyst** — asks revenue questions ("total net revenue last week"), currently reconciles finance dashboards with engineering's numbers by hand.
- **Engineering/capacity lead** — asks usage and quota questions ("API requests by model type this quarter," "effective RPM for account X"), currently checks Grafana/Metabase and quota history separately from revenue.
- **Customer-facing team member** — no supported question path in v1; explicitly deferred until the customer-service semantic model exists. Named here so downstream roles know this persona exists and is intentionally unserved in v1, not overlooked.

## User Stories

1. As a finance analyst, I want to ask "What was total net revenue last week?" in plain language, so that I get a governed number without opening a dashboard or pinging an analyst.
2. As a capacity engineer, I want to ask "Show total API requests by model type this quarter," so that I can see usage broken down by a dimension the semantic model already governs, without writing SQL.
3. As any user, I want the system to tell me clearly when it cannot answer, so that I never mistake a rejection for a real answer or get an approximated/wrong number.
4. As any user, I want relative time phrases to resolve consistently against today's real date, so that the same question asked on different days returns comparable, correct time windows.
5. As the program owner, I want every routing decision measured against a domain-balanced eval set, so that the 95% correctness claim is evidence, not a guess.

Full metric type (leading/lagging), instrument, and ownership: `doc/8.PRD_DETAILED.md`.

## Out of Scope / Future Work

- Multi-step LangGraph agent investigations.
- Customer-service domain, once its semantic model and governed metrics exist.
- Disambiguation dialogue in place of rejection.
- Production/hosted multi-tenant deployment, pricing, and packaging.
- Any expansion of dimensions or metrics beyond what the existing semantic models already govern.
