## What This Is

A local, self-contained analytics case study built on **synthetic data** modeling
an AI-inference platform (customers consuming AI models across AWS regions). It
exists to demonstrate a governed metrics stack end to end: raw data → dbt medallion
transformations → a MetricFlow semantic layer → a conversational BI surface that
answers business questions **only through governed metrics**.

Everything runs locally on Postgres. No cloud dependencies, no real customer data.

## Scope: Cross-Domain Reporting Surface

This is not a revenue tool. It is one governed surface answering questions across
multiple domains, each owned by a different team but sharing one metric definition:

| Domain | Audience | Status |
|---|---|---|
| Revenue | RevOps / finance | Built |
| Token usage | Engineering / capacity | Built |
| Quota / rate limits | Engineering / capacity | Built |
| Customer service | Support | Planned — needs its own semantic model + metrics before it is queryable |

The value is a single trustworthy answer that crosses these silos. Cross-domain
metric routing is harder than single-domain because the domains share vocabulary
("requests", "limits", "usage") — the LLM must resolve to the correct governed
metric regardless of domain.

## The Data (synthetic)

Domain is an AI-inference platform. Grain of the world:

- **Customers** (`account_id`) — segment, vertical, account size, company name
- **Models** (`model_variant`) — e.g. proprietary vs open source, publisher, accelerator
- **Regions** (`source_region`) — AWS-style region codes
- Facts: per-request token usage, daily revenue, quota / rate-limit history, resource utilization

Source data lands append-only in the `raw_bronze` schema (loaded by ingestion
scripts and Airflow DAGs), then flows through dbt.

## Semantic Layer

Three semantic models feed the governed metrics:

| Semantic model | Backed by | Grain |
|---|---|---|
| `customer_revenue_weekly` | `ref('customer_revenue_weekly')` | account × week |
| `customer_quota_weekly_history` | quota mart | account × model × week |
| token usage semantic model | token usage mart | customer/model × period |

Governed metrics (69 total):

- **Revenue (32)** — gross/net revenue, net revenue USD, revenue per customer,
  YTD revenue, WoW/MoM absolute and % changes at customer and model+region grain
- **Token usage (22)** — tokens consumed, API requests, input/output tokens,
  error rate, tokens per request, mean/peak/p95 RPM & TPM, active-minute %, WoW deltas
- **Quota (15)** — effective RPM/TPM, peak utilization, actual requests/tokens,
  pending request metrics, adjusted vs default limits

## BI Surfaces

Two surfaces sit on top of the gold layer / semantic layer:

| Surface | Runs where | Connects via | Notes |
|---|---|---|---|
| **Metabase** | In Docker Compose (`metabase` service, port 3000) | Direct to local Postgres | Dashboards on `mart_gold`; local, no tunnel needed |
| **Hex** | Cloud-hosted | Warehouse connection to Postgres | Cloud, so it cannot reach local Docker Postgres directly — see caveat |

**Hex connectivity caveat:** Hex is SaaS. To reach the local warehouse it needs one of:
a secure tunnel (Tailscale / ngrok) exposing the Postgres port, or the gold schema
mirrored to a reachable warehouse.

## LLM Provider (BYOK / pluggable)

The conversational layer is **provider-agnostic**. No provider is hardcoded.

- Bring-your-own-key: OpenAI-compatible, Anthropic, or a local model
- Provider is selected by config/env, not baked into the app
- The LLM only maps natural language → a governed metric + dimensions + time range.
  It never sees or generates warehouse SQL.

---

## Rules for the Conversational BI Layer

Non-negotiable governance rules for any agent or app querying this data:

1. **Query only through MetricFlow.** Use `mf query` against governed metrics.
   Never generate raw SQL against the warehouse.
2. **Reject unknown metrics.** If a question maps to a metric that does not exist,
   reject it rather than approximating with SQL.
3. **Resolve time relative to a real reference date**, not a hardcoded one.
4. **Dimensions come from the semantic models** (segment, vertical, account_size,
   company_name, model_variant, source_region, inference_scope, time grains).
5. **BYOK stays pluggable.** Never hardcode a single LLM provider.

## Agent Orchestration (LangGraph)

Simple lookups (one metric, one time range) run as a direct provider call →
`mf query`. No framework needed. **Multi-step investigations** need an agent loop,
and that is where LangGraph is used.

Canonical use case — "Why did net revenue drop last week?":

1. **Detect** — query `wow_net_revenue_pct_change`, confirm the drop is real.
2. **Decompose** — break down by `segment`, `model_variant`, `source_region` to
   locate where the drop concentrates.
3. **Correlate** — pull `total_tokens_consumed` and `effective_requests_per_minute`
   for the same slice: did demand fall, or did quota throttle it?
4. **Branch** — usage held but revenue fell → pricing/discount; usage fell →
   demand or throttling. Each branch runs different follow-up metric queries.
5. **Synthesize** — narrate the finding with the supporting numbers.

Design rules for the agent:

- Each **governed metric is a tool**. The LLM chooses the next tool from prior results.
- All tools execute through **MetricFlow** — the agent still never writes SQL.
- Use **LangGraph** (not linear LangChain) for the explicit branching at step 4.
- State (findings so far) is carried across the graph; retries on empty results.

## Working Commands

Run from the dbt project directory:

```bash
dbt deps
dbt debug
dbt parse
dbt build
mf validate-configs
```

Smoke-test governed metrics:

```bash
mf query --metrics total_net_revenue --group-by metric_time
mf query --metrics total_tokens_consumed --group-by metric_time
mf query --metrics effective_requests_per_minute --group-by metric_time
```

## Do Not

- Do not bypass MetricFlow with hand-written SQL in the BI layer.
- Do not commit `target/`, `dbt_packages/`, `logs/`, or `.DS_Store`.
- Do not treat this data as real — it is synthetic and for demonstration only.
