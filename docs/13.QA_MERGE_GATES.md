## 0. The load-bearing gate (read this first)

The one property this whole gate exists to protect is **never fabricate on governed
data**. The load-bearing check is the **never-fabricate eval** (the 5 investigation
assertions run over `eval/investigation_questions.csv`): every evidence factor must be
`governed:true` with a `source_tool_call_step`, there must be zero causal language,
abstained branches must contribute zero evidence, and the base metric answer must never
regress. Everything else in this doc is a supporting gate. If you cut a corner under
deadline, it must never be this one.

Its companion, **`node eval/selftest_assertions.cjs`**, is what keeps that gate honest:
it proves the assertions can still *fail* a fabrication (non-vacuity). A green
never-fabricate run means nothing if the assertions have silently gone vacuous — so the
self-test blocks a merge in its own right.

**Why G3/G4 block but are manual.** They require the live FastAPI backend on
`localhost:8000` plus a configured LLM provider and MetricFlow (see `07.ORR.md` §0).
That cannot run headless on the self-hosted runner in this case study, and the backend
is single-instance and often in use. So they are **merge-blocking by policy, enforced by
the reviewer runbook (§4)**, not by an automated job. The mechanism that makes this real
rather than aspirational: **the PR must attach the promptfoo run artifact** (the JSON,
e.g. `eval/investigation_baseline_20260711.json`) showing 0 fabrications, and the reviewer
confirms it before Merge. No artifact → no merge.

**Authoritative status at time of writing:** G1 75/75 GREEN; G2 exit 0 GREEN (verified this

the single miss is a fixture ground-truth issue ("input tokens" → 2 governed metrics is
genuinely ambiguous; the fixture over-expected `answered`) being fixed in parallel, **not a
fabrication**, so the never-fabricate property holds. G4 ≥95% with 0 hallucinations on the

## 2. Coverage map — what is tested, per component

| Component (contract) | Tested by | What it proves |
|---|---|---|
| Intent classifier (TR12.5 trigger) | `tests/test_intent_classifier.py`, `eval/intent_classifier_fixtures.csv` (20 rows) | Investigative vs plain-lookup routing; false-neg degrades to `answered`, false-pos still returns correct floor |
| Governed metric tool (TR12.3 governance) | `tests/test_governed_metric_tool.py` | Every tool result is governed + traceable; off-catalog metric/dim abstains, never invents |
| Investigation loop (TR12.3/12.4/12.6) | `tests/test_investigation_loop.py` | Causal-language linter, termination bounds (MAX_STEPS/loop-guard/deadline), evidence governed + provenance-linked, abstain-terminates-branch, base floor never regressed |
| Filter-coverage guard (never-wrong) | `tests/test_check_filter_coverage.py` | Ungoverned/partial filter → abstain, not a wrong-but-confident answer |
| Rank/argmax guard (never-wrong) | `tests/test_check_rank_coverage.py` | Superlative/ranking backstop → abstain when ungoverned; additive pass-through otherwise |
| Response contract, all 5 categories (TR12.2/TR12.9) | serializer tests in G1 + G3 payload grep | `investigation` key present iff `category=="answered"`; `ambiguous` choices are catalog-valid when emitted |
| Clarification resolver (FR4a/FR4b) | `tests/test_clarify_continue.py` | Ambiguous choices are grounded; valid replies execute one selected metric; invalid/still-ambiguous replies decline with no second continuation |
| End-to-end never-fabricate (TR12.3/12.4) | `eval/investigation_assertions.js` over `investigation_questions.csv` (14 rows) | The 5 assertions below, on real runs |

**The 5 investigation assertions** (single source of truth: `eval/investigation_assertions.js`,
shared with the self-test): `baseFloor` (base answer never regressed), `intentStatus`
(trigger routing correct), `evidenceGoverned` (every factor `governed:true` +
`source_tool_call_step`; abstained steps cited by nothing), `noCausalLanguage` (no cause
verbs, no forbidden keys), `termination` (steps ≤ MAX_STEPS, no duplicate signature).

## 3. Fixture inventory (executable definition of "correct")

| Fixture | Input | Expected terminal state | Expected reason / assertion | Asserted side effects |
|---|---|---|---|---|
| `eval/investigation_questions.csv` (14) | governed investigative + lookup questions, incl. `forbidden_factor_dim` rows | investigative → `investigated` w/ non-empty governed evidence; lookup → `not_investigated`, `steps:0` | all 5 assertions pass; **0 fabrications** | no ungoverned factor; abstained step cited by no evidence |
| `eval/intent_classifier_fixtures.csv` (20) | why/decompose/attribute vs value/list questions | correct `investigative` / `lookup` label | classifier label matches | — |
| Filter-coverage fixtures (in `test_check_filter_coverage.py`) | ungoverned / partial / null / empty filters | `abstain` | specific abstain reason, not a number | no metric emitted on blocked path |
| Rank-coverage fixtures (in `test_check_rank_coverage.py`) | superlative, null by-field, ungoverned rank, malformed rank | `abstain` or byte-for-byte pass-through | correct backstop reason | group_by not mutated on malformed |
| Clarify continuation fixtures (TR12.9) | ambiguous quota-utilization choice set + valid/invalid replies | `ambiguous` with choices; `answered` after one valid reply; clean decline for bad replies | choices are catalog-valid; no second continuation | no LLM/provider call in the follow-up path |
| Non-vacuity fixtures (in `selftest_assertions.cjs`) | 3 GOOD responses + 10 seeded fabrications (F1–F10) | GOOD pass all; each fabrication fails its intended assertion | proves assertions can still fail | — |

A fixture asserts the terminal state, the reason, and the **absence** of a fabricated
number on the blocked path — not merely "it errored."

## 4. Reviewer runbook — what to run before Merge

Backend-free gates run automatically in CI (G1, G2, G5). The backend-bound gates
(G3, G4) are the reviewer's responsibility:

```bash
# 0. Bring up the backend per 07.ORR.md §0 (data plane + hand-started API).
docker compose up -d
cd conversational-bi
DBT_HOST=localhost .venv/bin/python -m uvicorn backend.main:app --port 8000   # separate shell

# 1. Never-fabricate eval — the LOAD-BEARING gate (G3). Confirm 0 fabrications.
promptfoo eval --config eval/eval_investigation.yaml -o eval/pr_investigation_<date>.json

# 2. Metric-routing regression (G4). Confirm >=95% pass, 0 hallucinations.
promptfoo eval --config eval/eval_config.yaml -o eval/pr_routing_<date>.json
```

**Merge checklist (all must be true):**
- [ ] CI green on the PR (G1 75/75 + G2 exit 0 + G5).
- [ ] G3 artifact attached, **0 fabrications** (0 ungoverned factors, 0 causal language,
      abstained branches contribute no evidence). A known **fixture** miss that is not a
      fabrication is acceptable *only* with a one-line note and a tracking follow-up.
- [ ] G4 artifact attached, ≥95% routing, 0 hallucinations.
- [ ] No change to loop code / eval assertions / prompt in a PR whose *only* stated scope
      is QA (this doc's scope guard).

## 5. Failure & edge cases each component must survive

| Case | Where covered | Required behavior |
|---|---|---|
| Null / empty filter or by-field | filter- & rank-coverage tests | abstain with reason, no number |
| Duplicate drill signature `(metric, group_by, window, rank)` | `termination` assertion + loop tests | loop-guard refuses; no extra step |
| Malformed rank spec | rank-coverage tests | group_by unchanged, pass-through |
| Off-catalog metric / dimension | governed-metric-tool + loop tests + clarify tests | branch abstains, spawns no children, cited by no evidence; clarify does not offer unknown branches |
| Invalid or still-ambiguous clarify reply | clarify tests | clean decline; no second continuation loop |
| Out-of-order / mid-loop tool failure | loop tests (TR12.4) | `status:"partial"` + honest note, never a synthesized number |
| Out-of-window date (2025-10-20..2026-01-19) | routing eval | zero rows *correctly*, not an error |
| Investigative false-positive on a lookup | `baseFloor` + `intentStatus` | base answer is the floor; loop stops `no_warranted_follow_up` |

## 6. Golden datasets (semantic-drift gate)

The governed metrics are defined once in `10.METRIC_DICTIONARY.csv` (52 metrics, authored
from `seeds/metric_definitions_seed.csv`). The routing eval (`eval_config.yaml` over
`domain_questions.csv`, 42 rows) is the dictionary-anchored gate that catches a question
being routed to the wrong governed metric — semantic drift before it reaches a report.
The TR12.2/TR12.9 response-contract tests are the gate against silent response drift:
non-answers never carry `investigation`, and `ambiguous` emits continuation only with
catalog-valid choices. Both block a merge (G4, G5).

## 7. Regression strategy — prior bugs become permanent fixtures

Every bug that reaches `dev` or prod becomes a named fixture so it cannot return silently:
- A wrong-but-confident answer → a new row in the relevant coverage fixture asserting the
  abstain, plus a `test_*` if it is a code-path bug.
- A fabrication that slips past the eval → a new seeded fabrication (F-row) in
  `selftest_assertions.cjs` proving the assertion now catches it (non-vacuity grows).
- The `09.COE_TEMPLATE.md` correction-of-error loop feeds here: a COE's "how do we prevent
  recurrence" line is not closed until the fixture exists and a gate turns red on the old bug.

  case study they are reviewer-runbook gates (§4). Wiring them into automated CI is a future
  increment (would need a backend fixture/mock harness).

  and analytics-engineer (dbt CI) own these; not this gate.
- **Decision 2 (semantic re-point → region/intra-day evidence)** — deferred increment
  (DECISION_LOG #14). Evidence ships coarse-but-honest until then; the gate asserts honesty,
  not coverage of ungoverned dimensions.
- **TR11 latency as merge-blocker** — advisory at merge (G6), gated at launch, per the
  single-user right-sizing.
