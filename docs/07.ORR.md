|---|---|
| FastAPI process | `/health` returns service status. |

| Catalog freshness | `catalog_for_llm.yaml` is not older than `semantic_manifest.json`. |
| LLM reachability | Configured provider smoke test passes or returns clear `system_error`. |
| Credential safety | Logs exclude API keys and credential fields. |

## Observability

The ORR requires a JSON Lines request log containing:

- input question
- outcome category
- selected metric
- resolved time window
- `mf query` command
- elapsed time
- error detail for `system_error`

The log must never serialize the raw request object because that can leak BYOK credentials.

## Failure Modes

| Failure | Required Behavior |
|---|---|
| LLM unreachable | Return `system_error`, not product rejection. |
| LLM invalid JSON | Return `system_error` and log truncated raw output. |
| Unknown metric | Return `unknown_metric`; do not execute MetricFlow. |
| Invalid dimension | Return `unknown_metric` or omit before execution per design. |
| `mf` missing | Return actionable `system_error`. |
| MetricFlow timeout | Return `system_error` within latency budget. |
| Zero-row valid result | Return `answered` with row count 0. |

## Rollback

For the local prototype, rollback means returning to the direct single-question MetricFlow path and disabling any agentic/RAG workflow until the failing component is corrected. No production rollback automation exists because no production deployment is in scope.

## Support Runbook Requirements

Support must be able to answer:

- Is the service up?
- Is `mf` installed and working?
- Is the semantic catalog stale?
- Which provider was selected?
- Was the result an answer, product rejection, or infrastructure failure?
- Which metric and query produced the value?
