## Why this guide

**Agentic BI** — AI that plans multi-step analysis, monitors your metrics over time, and proactively surfaces decisions or acts, with a human in the loop — is coming to every analytics roadmap. The instinct is to ask "which AI model should we buy?" That is the wrong first question. **An agent is only as trustworthy as the data underneath it**, and the leaders who win with agents will be the ones who got their data house in order first. This guide is about the handful of data truths a leader must internalize, the questions to ask your data team, and how to tell whether your data is ready for agents at all.

First, the one distinction that frames everything. *Conversational BI* answers a governed question **on demand** — you ask, it answers or declines. *Agentic BI* is different in one word: **autonomy**. An agent takes several steps on its own — pulling numbers, comparing them, drawing a conclusion — before a human sees the result. That autonomy is exactly why the data foundation stops being a technical detail and becomes a leadership concern.

## The six data truths

### 1. Agents amplify data quality — good and bad — faster than a human can catch it

A human analyst working with a flawed number usually senses something looks off. An agent runs many steps in seconds and hands you a conclusion. If the underlying data is wrong, the agent doesn't slow down — it scales the mistake and delivers it with confidence. **The upside is symmetric:** on well-governed data, an agent scales your best analyst's discipline. This is the core reason the data foundation must come before autonomy, not after.

### 2. The governed semantic layer is the real moat — not the model

A **semantic layer** is the place where every business metric is defined exactly once ("net revenue means *this*") and served to any tool by a stable contract — a dependable interface that calls the metric by name. This, not the choice of AI model, is what makes agent answers trustworthy and consistent. Models are increasingly interchangeable; a single canonical definition of your metrics that every agent must use is durable and hard for a competitor to copy. *Ask your team: is each key metric defined in exactly one governed place, or re-derived differently in every dashboard and spreadsheet?*

### 3. The trust boundary: the agent selects and phrases — the governed layer supplies every number

The safe architecture keeps a hard line: the AI is allowed to **choose** which approved metric answers your question and to **phrase** the response, but it never writes its own database queries and never becomes the source of truth. Every quantitative number comes from the governed layer, validated against the approved catalog before anything runs. This boundary is what makes an agent's answer inspectable — you can always see which governed metric produced the number. A leader should insist this boundary is architectural, not a matter of trusting the model to behave.

### 4. Abstention and traceability: an agent must be able to say "I don't have that"

A wrong number delivered confidently is worse than no number. An agent must be built to **abstain** — to return a clear "I can't answer that" when a question is ambiguous, unsupported, or outside its governed data — and every answer it *does* give must **trace back to a real source**. These two properties, honesty about limits and a traceable line back to origin, are the minimum bar before you let an agent act with any autonomy. *Ask your team: when our system doesn't know, does it say so — or does it guess?*

### 5. Freshness: an agent must know how current its data is before it acts

A human knows yesterday's dashboard is a day old and adjusts. An agent will act on whatever it is given as if it were current, unless the data itself carries its freshness. **Freshness SLAs** — an agreed, monitored guarantee of how up-to-date each dataset is — are what let an agent decide whether it is safe to act now or must wait. Acting autonomously on stale data is one of the fastest ways an agent can cause harm quietly. *Ask your team: for the data an agent would act on, do we know and monitor how fresh it is?*

### 6. The foundation is built in four layers — each earns the agent one guarantee

The trusted data foundation is assembled in four layers (the industry calls this a "medallion" architecture). A leader doesn't need the plumbing — only what each layer *guarantees* an agent:

- **Bronze — the faithful record.** Raw source data captured as-is, origin traceable. *Guarantee:* nothing is invented; any conclusion can be traced back to a real source.
- **Silver — the clean, consistent layer.** De-duplicated, correctly typed, integrity-checked so records link up properly, with known freshness. *Guarantee:* the facts an agent reads are internally consistent and current — no contradictory or orphaned records.
- **Gold — the business-ready truth.** The curated, agreed-upon tables the business already uses to decide. *Guarantee:* the agent reasons over the same numbers leadership trusts, not a private re-derivation.
- **Semantic layer — the one canonical definition.** Every metric defined once, callable by contract, validated against the approved catalog. *Guarantee:* a metric means one thing every time, an agent cannot silently redefine it, and it can only use approved metrics.

Two things run across all four layers: **freshness SLAs** (truth 5) and the **stable metric contract** (truth 2). Together, these layers are the prerequisite for trusting an agent — build them before autonomy, not after.

## Proof-point: we tested these truths on a real build

We are not asking leaders to take this on faith. We built a working **Conversational BI** system on a fully open-source stack (Postgres, Airflow, dbt Core, MetricFlow, Docker Compose) that puts every truth above into practice: a person asks a plain-English question across revenue, usage, and capacity; the AI only *selects* from pre-approved governed metrics; the choice is validated against the catalog; the answer runs only through the governed metric engine; and the system **abstains** rather than guess.

What the honest numbers showed:

- **Before guardrails (truthful baseline):** roughly **44% overall / 52% on category routing / 4-of-6 on metric selection** on a balanced question set. (An earlier "100%" reading was a broken test that checked nothing — we caught and fixed it, a lesson in itself: distrust any unaudited accuracy claim.)
- **After the governance guardrails:** on the questions it *chooses* to answer, precision rose from ~70% → ~84% → **~96%**, with **zero fabricated answers on governed data**.
- **The deliberate trade-off:** it now answers a **narrower** set of questions (**coverage ~25–33%**) because it abstains far more readily — "trustworthy and modest" chosen over "broad and occasionally wrong."

**The single most important finding:** the accuracy gains came from the guardrails and the governed data layer — **not from a bigger or smarter AI model.** The model was already answering the answerable questions. Everything above is about data, not models — and that is the whole point of this guide.

## What a leader should do now

**Ask your data/analytics team these five questions:**

1. Can we define our single most important metric **exactly once**, in one governed place — or is it re-derived differently across dashboards and spreadsheets?
2. Can any tool retrieve that metric **by a stable contract**, so its definition can't shift underneath an agent?
3. When our system **doesn't know** the answer, does it clearly say so — or does it guess?
4. Can we **trace** any given number back to its source data?
5. Do we **know and monitor how fresh** the data an agent would act on actually is?

**The simple readiness test.** For your top metric: *can we define it exactly once, serve it by contract, trace it to source, and know its freshness?* If yes on all four, you have the foundation an agent needs and can pilot autonomy on that metric with a human in the loop. **If not, that gap is the backlog to build before autonomy — not after.** An agent on ungoverned data is a liability multiplier; the same agent on a governed foundation is a force multiplier. The difference is entirely in the data work you do first.

## Open questions for the human (flagged, not assumed)

1. **Unsigned commercial claims.** This guide deliberately states **no pricing, no launch date, and no ROI or competitive figures** — none are signed off in the source docs, and `docs/08.Launch.md` explicitly forbids production-ready, real-customer-ready, and unmeasured-ROI claims. Any such claim needs explicit human sign-off first.
2. **Which accuracy frame to lead with.** The source docs contain more than one accuracy reading depending on the question set (a ~44% honest baseline on the full balanced set vs. much higher routing accuracy measured only on the answerable subset). This guide uses the conservative full-set baseline plus the guardrail gains, to avoid overstating. Confirm that is the framing leadership should see.
3. **Scope of "Agentic BI" as a commitment.** This guide frames Agentic BI as a *direction requiring a foundation investment*, not a funded roadmap item. If leadership will read it as a commitment to build, that is a scope decision the TPM should gate before circulation.
