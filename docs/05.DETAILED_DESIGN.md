## Data Architecture

The platform is a local Postgres medallion stack:

`raw_bronze -> staging_silver -> fact/dim gold -> MetricFlow semantic layer`

Gold layer (per GATE A, 2026-07-06 — see DECISION_LOG.md #1; designs in tmp/TASK1_DESIGN.md, content canonical here after Task 8):

| Fact | Grain (one row per…) | Notes |
|---|---|---|
| `fct_revenue_daily` | account × model_variant × product_sku × billing_type × inference_scope × source_region × **day** | Dim attributes stripped; joined via entities at query time. |
| `fct_token_usage_minute` | account × model_variant × inference_scope × source_region × inference_region × traffic_type × **minute** | Minute grain preserved for peak/p95/active-minute metrics. |
| `fct_quota_weekly` | account × model_variant × inference_scope × source_region × **week** | Stateful weekly snapshot; renamed from `customer_quota_weekly_history`. |

Conformed dims: `dim_customer`, `dim_model`, `dim_region`. Weekly/monthly rollup marts are obsolete — grain is a query parameter; dashboard rollups come from MetricFlow saved-query exports (quota fact exempt). PK/FK are declared via dbt `constraints:` in Postgres and drive semantic-model generation.

The semantic layer has 3 domains and 52 governed metrics (collapsed from 73 YAML metrics; `10.METRIC_DICTIONARY.csv` is the canonical list):

| Domain | Count | Source |
|---|---:|---|
| Revenue | 17 | `models/metrics/metrics_revenue.yml` (GENERATED) |
| Token usage | 20 | `models/metrics/metrics_token_usage.yml` (GENERATED) |
| Quota | 15 | `models/metrics/metrics_quota.yml` (GENERATED) |

Metric authoring surface is `seeds/metric_definitions_seed.csv` (17-column schema, GATE A ruling 5); `scripts/generate_metric_yaml.py` generates the metric YAML before every parse, and CI fails on drift between seed and generated files. Hand-editing generated YAML is forbidden. WoW/MoM metrics are MetricFlow `derived` (offset_window), YTD are `cumulative` (grain_to_date) — parity with old mart values gated at GATE B. Semantic-model YAML is drafted by `scripts/generate_semantic_models.py` from Postgres information_schema + declared PK/FK, human-reviewed before commit.

Every metric change must re-enter the metric certification gate (edit the seed, regenerate, revalidate). No consumer computes governed values outside MetricFlow.

## Request Flow

1. User submits a question to `/query`.
2. API loads or rebuilds `catalog_for_llm.yaml` from `semantic_manifest.json`.
3. LLM returns structured metric-selection output.
4. Backend validates metric and dimensions server-side.
5. Translator resolves time and constructs `mf query`.
6. MetricFlow executes against the dbt semantic layer.
7. API returns `answered` or one of four non-answer categories.

## Guardrail Enforcement

| Guardrail | Enforcement Point |
|---|---|
| No raw SQL | `MetricFlowTranslator` is the only data access chokepoint. |
| No invented metrics | Manifest set-membership check before execution. |
| No invented dimensions | Valid-dimension check before execution. |
| Unsupported domains rejected | LLM/classifier disposition plus category contract. |
| Infrastructure failure separated | `system_error` distinct from product rejections. |
| BYOK protected | Credentials excluded from logs and not silently substituted. |

## Agentic Investigation Loop + Evidence-from-Governed-Data (APPROVED — gate-2 2026-07-11, DECISION_LOG #13/#14)

**PIVOT (retires the prior ticket-RAG premise).** Evidence is no longer a separate support-ticket text corpus retrieved via RAG. The prior fixture (`evidence_retriever.py`, `FIXTURE_TICKETS`) used fabricated foreign keys (`ACME-1234`, `GLOBEX-5678`, `INITE-9012`) absent from `dim_customer` (real `ACCnnn`) and described a different product (Auth0/Redshift/Stripe) — fabrication, governed-around. It is **retired at the root**. Evidence is now a **governed decomposition of the metric movement itself**, produced by a bounded multi-step agentic loop, every number a governed MetricFlow query. No corpus, no seed, no vector store for evidence.

### Loop architecture (software-architect, 5.1)

- **Fresh loop; salvage the LangGraph `StateGraph` scaffold + `route_to_metric_node` + the `SynthesisOutput` pydantic-contract pattern.** `agent_graph.py`'s ticket nodes (`retrieve_evidence_node`, synthesis ticket-tiers) are deleted.
- **Nodes:** `plan → run_governed_metric → observe → decide → (loop back or) synthesize → END`. The base metric answer is computed first and is the **guaranteed floor** — investigation is strictly additive. A non-`answered` base short-circuits to synthesize and returns that category unchanged (TR12 preserved).
- **One tool — `GovernedMetricTool` — is the ONLY data access.** Nodes cannot touch Postgres, emit SQL, or call `mf` directly; they emit a structured intent `(metric, group_by[governed dims only], time_window, rank?, filters?)` and the tool routes through the same Step-1 guards (`_check_unknown_metrics`, `validate_dimensions`, `check_filter_coverage`, `check_rank_coverage`, `mf query` only). Off-catalog metric/dimension → that branch abstains.
- **Termination bounds (bounded investigator):** `MAX_STEPS=6` (1 base + ≤5 drills), `MAX_DEPTH=3`, cumulative latency ≤ TR11 (30s p95), no-warranted-follow-up stop, visited-signature loop-guard `(metric, sorted(group_by), window, rank)` refuses duplicates, and **abstain-terminates-branch** (a non-`answered` drill spawns no children — never fabricate to continue).
- **Trigger = Decision 1 (A), APPROVED:** the loop fires only on **investigative intents** ("why did X change", "what drove Y", "break down Z"). Plain lookups keep the existing single-shot `answered` shape untouched — backward-safe, no latency tax on trivial questions. Requires an intent classifier (ai-architect, 5.4).

### Evidence semantics (data-architect, 5.2)

For a movement in metric M between baseline t₀ and current t₁, evidence = at most four governed elements, nothing else: **movement** (measured delta + % change), **dimensional contribution** (members of one governed dim ranked by signed delta + `share_of_total_delta`), **time localization** (movement across sub-periods at the finest governed grain), **coincident signal** (a *different* governed metric over the same slice/window, presented in parallel, never joined into one sentence). Derived, not stored.

**Decomposition query contract (the loop's tools bind to these; all governed MetricFlow, no raw SQL):**
- **T1 `metric_total(metric, window)`**, **T2 `decompose_by_dimension(metric, dim, window)`** (precondition: `dim ∈ catalog[metric].valid_dimensions` AND metric additive), **T3 `contributors_by_delta(...)`** (T2 twice, client-side subtraction of two governed totals, rank by |delta|, share = member_delta / total_delta; abstain if baseline total = 0), **T4 `coincident_signals(...)`** (probe other governed metrics over the same slice, returned in a **separate list**).
- **`EvidenceBundle`** return schema carries `movement`, `decomposition|null`, `time_localization|null`, `coincident[]`, `coverage{decomposable,reason}`, `provenance{no_raw_sql,no_external_corpus}`. Every element carries an explicit `claim_type`; there is **no `cause` field and no free-text narrative field** — causation is structurally unrepresentable.

### Governance — correlation, never causation (non-negotiable, structural)

1. Recorded-vs-inferred is a **field** (`claim_type` + `inference[]`), not a label — a `measured_delta` is a governed fact; the ranking and the coincident-pairing are inferences, tagged as such.
2. **No causal representation exists** in the schema. Strongest statement: "M fell by Δ; member X accounts for share S of Δ; metric N also moved by Δ′ in the same window" — three parallel governed facts.
3. Coincident signals are structurally disjoint (`coincident[]`, own provenance) — "co-moved" is the only asserted relationship.
4. Field names are `contributor`/`share_of_total_delta`, never `driver`/`cause`. A **post-synthesis causal-language linter** scans the narrative for cause verbs ("caused/because/drove/led to/due to") and downgrades to correlational or fails synthesis toward abstention. This linter is the mechanism RAID's "RAG evidence implies unsupported causality" demands.
5. **Non-additive metrics cannot claim contribution at all** — ratios (`error_rate`, `revenue_per_customer`, `*_utilization_pct`) and extrema/percentiles (`peak_rpm`, `p95_*`) have per-member deltas that don't sum to the total delta; the loop reports per-member values but abstains from any "X drove it" framing (read `agg` from the manifest).

### Response shape — additive extension of the five-category contract (solutions-architect 5.3 ratifies in TRD)

The `answered` category gains an additive `investigation{status, steps_taken, stopped_reason, trace[], evidence[]}` block. The **four non-answer categories are byte-for-byte unchanged**; existing clients ignore the new keys. Every `evidence[]` record carries `relationship:"correlation"`, `governed:true`, and `source_tool_call_step` (replayable/auditable). Abstained drill branches appear in `trace[]` with their real category and contribute nothing to `evidence[]`. Mid-loop failure → `status:"partial"` + honest note, never a fabricated fill-in.

### Coverage limits with TODAY's semantic layer (Decision 2 DEFERRED — re-point is a later increment)

Semantic models are currently **rollups** (weekly/monthly), not the fine-grained `fct_` marts. So today evidence **cannot**: localize a spike intra-day/sub-week; break token usage down by `source_region` (no region dim on token semantic models); decompose customer × model simultaneously. Additive revenue/token/quota-`actual_*` decomposition by their exposed dims **works**. Re-pointing semantic models at `fct_revenue_daily`/`fct_token_usage_minute` (analytics-engineer) unlocks region + intra-day evidence — **deferred to its own increment** per gate-2. The loop reads valid dimensions from the catalog at runtime and **abstains honestly** on anything ungoverned — coarse-but-honest, never fabricated.

### Deferred (gate-2 2026-07-11)

- **Decision 2** — semantic-model → `fct_` re-point (fuller region/intra-day evidence): its own increment, human-approved when awake.
- **Decision 3** — author `docs/2.TOOLSTACK.md` (both architects flagged no toolstack guardrail is formally in force): deferred, non-blocking.

### Retained boundary

RAG-retrieves-context-only strengthens into: **evidence IS governed metric computation.** It may state contributing factors and coincident signals; it may never compute a metric outside MetricFlow, assert causation, or cite a fabricated source. The eval rows classifying "support tickets" as `unsupported_domain` (DECISION_LOG #10) remain correct — support tickets are genuinely not a governed domain.

## Known Design Gaps

- Domain tagging in `catalog_builder.py` must derive from metric YAML source or explicit metric tags, not a hardcoded partial list.
- `model_type` semantic meaning needs confirmation before prompt/eval design depends on it.
- An earlier context draft misstated "3 semantic models"; the corrected architecture is 3 domains and 11 semantic models.
- Anthropic BYOK signature path and hardcoded reference date need implementation fixes.
- `/health` should check `mf`, catalog freshness, and LLM reachability, not only process liveness.
