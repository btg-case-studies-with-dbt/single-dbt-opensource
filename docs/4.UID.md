# UI Details: Governed Metric Execution Architecture

**Status:** Draft for review
**Owner:** Design
**Date:** 2026-07-02
**Source inputs:** Consolidated from the project UI notes into the canonical documentation chain.

## Experience Goal

The UI should feel like a precise local engineering tool: one input, one governed answer, or one clear reason the system cannot answer. It must never imply conversational memory, metric invention, or narrative certainty that the backend does not support.

## Design Tenets

- Honesty over confidence.
- One box, one question, one truth.
- Governed and visibly traceable.
- Discoverable without external documentation.
- Local-tool proportions, not enterprise chrome.

## Navigation

The canonical v1 information architecture has three tabs:

| Tab | Purpose |
|---|---|
| Ask | Submit one question and view one outcome card. |
| Metrics Dictionary | Browse governed metrics, domains, dimensions, and valid grains from `/catalog`. |
| Instructions | Show example questions, time-range behavior, and outcome explanations. |

## Primary Screen: Ask

Must include:

- Header with product name, domain badges, and provider/model configuration.
- Question input bar.
- Outcome card region.
- Session history list for this page session.

## Outcome Categories

The UI renders from the backend `category` field only:

| Category | Treatment |
|---|---|
| `answered` | Neutral success card with metric name, value, time range, dimensions, and collapsed `mf query` provenance. |
| `unknown_metric` | Informative card pointing to the Metrics Dictionary. |
| `ambiguous` | Informative card explaining the wording maps to more than one governed metric. |
| `unsupported_domain` | Boundary card explaining the domain is not supported today. |
| `system_error` | Alert card with retry action; never counted as a product rejection. |

## Components

| Component | Rule |
|---|---|
| Question Input Bar | Accepts one independent question; does not imply memory. |
| Outcome Card | Visual treatment is driven only by `category`. |
| Answer Detail Table | Shows only valid MetricFlow dimensions. |
| Metrics Dictionary List | Reads from `/catalog`; never hardcodes metric lists. |
| Instructions Panel | Contains only examples that resolve to supported governed metrics. |
| Provider/Model Modal | Keeps BYOK settings out of visible logs and console output. |

## Mockup Reference

## Explicit Non-Goals

- No narrative synthesis in v1.
- No root-cause report view in v1.
- No operator dashboard in v1.
- No threaded chat UI suggesting multi-turn disambiguation.
