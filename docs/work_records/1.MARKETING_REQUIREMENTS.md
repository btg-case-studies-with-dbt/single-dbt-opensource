## Positioning

An engineering architecture case study for governed agentic BI: natural-language questions route through approved dbt and MetricFlow metrics, while future RAG retrieves customer tickets and feedback as cited evidence.

## Target Audience

| Audience | Why They Care |
|---|---|
| Data and analytics engineers | Shows governed semantic-layer execution instead of text-to-SQL. |
| AI application architects | Shows where agent runtime, tool gateway, RAG, guardrails, and observability fit. |
| RevOps / finance / capacity stakeholders | Shows how cross-domain answers can stay tied to approved metrics. |
| Hiring / portfolio reviewers | Shows engineering architecture judgment and system boundaries. |

## Core Message

Agentic BI should not let an LLM become the source of truth. This project keeps quantitative answers in dbt and MetricFlow, uses the LLM for routing and synthesis, and reserves RAG for cited customer evidence.

## Messaging Pillars

### 1. Governed by construction

Every quantitative answer is tied to a certified MetricFlow metric and validated before execution.

### 2. Agentic without text-to-SQL

The agent can plan and retrieve, but the warehouse query path remains constrained to governed tools.

### 3. Evidence-aware, not evidence-confused

Support tickets and feedback explain context; they do not compute metrics.

## Allowed Claims

- Local architecture case study.
- Synthetic AI-inference platform data.
- dbt and MetricFlow governed semantic layer.
- LLM does not generate raw SQL.
- Open-source stack comparison included.
- Customer evidence RAG is an architecture extension, not v1 shipped functionality.

## Claims Not Yet Allowed

- Production-ready.
- Real customer-data ready.
- Customer-service metrics supported.
- Autonomous root-cause agent shipped.
- Measured ROI or productivity gain.
- Security/compliance readiness for PII.
